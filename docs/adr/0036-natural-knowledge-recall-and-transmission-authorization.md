# ADR-0036：自然知识召回、远传策略与一次性授权边界

- 状态：Accepted
- 日期：2026-07-16
- 决策者：项目所有者、Codex
- 关联版本/任务：知识库优化 K.0
- 取代：无
- 被取代：无

## 背景

ADR-0029～ADR-0035 已让用户明确导入的文件能够在本地解析、切片、建立 FTS/BGE-M3 索引，并在用户明确要求
查资料时提供可验证引用。现有对话默认不会在普通陪伴交流中查询用户文件。

陪伴型 Agent 最终需要在自然对话中想到可能相关的资料，但“本机发现资料相关”并不代表“用户允许把资料片段发送给
当前聊天模型”。如果把检索与传输合并成一个开关，会使在线 Provider 获得未经授权的文件正文，也会让知识事实污染
人格和相处记忆。

## 决策

1. 对话知识召回采用 `off / explicit / smart` 三种模式；任何旧库和新安装默认均为 `explicit`。K.0 不新增设置项，
   后续迁移也不得静默启用 `smart`。
2. `smart` 的第一道判断必须在本地完成，只能使用确定性规则、FTS、BGE-M3 和本地统计；不得调用远程模型决定
   是否读取本地文件。
3. 文档敏感性与远传策略分离。后续文档策略为 `remote_allowed / ask_each_time / local_only`；旧文档迁移为
   `ask_each_time`，敏感文档默认为 `local_only` 且不能设为 `remote_allowed`。
4. Provider 必须声明 `local / remote / unknown` 执行位置；`unknown` 始终按 `remote` 处理。不能仅凭供应商名称或
   `localhost` 字符串永久信任位置。
5. `ask_each_time` 文档向 remote/unknown Provider 发送片段前，后端签发短时、一次性 grant。grant 绑定会话、
   请求、查询指纹、Provider、模型、位置 revision、文档策略 revision、chunk ID 和正文哈希；数据库只保存 token 哈希。
6. 远程请求开始前，后端重新计算并核对允许集合，在同一安全边界消费 grant。前端的 `consent=true` 或 chunk 列表
   不能作为授权依据。拒绝、过期、重放、策略/位置/模型/来源变化均保守失败。
7. 自然召回先经过影子模式和固定评测。在达到误触发、安全、延迟和记忆隔离门槛前，不进入真实模型上下文。
8. 无论 explicit 或 smart，最终片段继续复用现有 citation 白名单、当前 chunk 哈希、document 状态和 locator 校验。
9. 知识正文是低权限引用数据，不能修改人格、安全规则或工具权限；记忆观察器只能收到受限引用元数据，不得把
   knowledge chunk 当作 Fragment、Episode 或 Saga 来源。
10. K.0 只冻结上述决策、威胁模型和评测骨架，不修改 schema、API、设置、检索或聊天运行逻辑。

## 威胁模型

| 威胁 | 必须采取的控制 |
|---|---|
| 本地命中后未经同意远传 | 文档策略、Provider 位置和 grant 三重核对 |
| 前端伪造同意或 chunk ID | 后端重算允许集合，不接受布尔同意 |
| grant 重放 | 随机 token、只存哈希、短时过期、原子单次消费 |
| 确认后切换模型或修改策略 | revision、模型和正文哈希任一变化即失效 |
| 删除/重建与远程请求竞态 | 请求开始前重新核对 document/chunk 当前状态 |
| 文档提示注入 | 知识块明确标为低权限数据，不进入系统指令层 |
| 知识污染相处记忆 | 观察协议区分引用事实、查阅行为和用户明确决定 |
| 审计泄露隐私 | 只保存指纹、原因码、数量、分桶和耗时，不存查询/正文/绝对路径 |
| 预检拖慢陪伴对话 | 本地硬超时，失败或超时直接回到普通对话 |

## 备选方案

### 每轮都检索并自动注入

- 优点：实现简单，看起来更“主动”。
- 缺点：误召回、远传和人格污染风险最高，普通陪伴对话也会增加延迟。
- 未采用原因：违反最少发送和默认兼容原则。

### 用远程模型判断是否需要知识

- 优点：分类表达能力较强。
- 缺点：为了判断是否读取本地文件，先向外部暴露用户消息；成本、网络和可解释性也不可控。
- 未采用原因：自然召回第一道判断必须本地可测。

### 只提供“允许知识库联网”总开关

- 优点：界面简单。
- 缺点：无法区分文档、Provider、当前模型和单次请求，也无法阻止旧同意被重放。
- 未采用原因：授权范围过大且不可审计。

## 后果

### 正面后果

- 未来可以自然使用资料，同时不改变现有用户默认隐私行为。
- 召回决策、传输许可和引用验证各自独立，故障可保守降级。
- 阈值必须由匿名固定评测决定，而不是写死未经验证的向量分数。

### 代价与限制

- 后续需要文档/Provider 迁移、授权状态机、确认 UI 和更多审计测试。
- `ask_each_time` 会在远程模型生成前增加一次用户确认。
- 智能模式在影子评测达标前不会真正改善回答。

## 安全与隐私

- 权限等级：本地检索为只读；正文远传为需要文档策略或逐次授权的外部副作用。
- 涉及的数据：用户消息、本地知识 chunk、Provider/model 元数据和无正文审计。
- 是否访问网络：K.0 不访问；后续只有有效策略/grant 才允许远程聊天请求携带片段。
- 用户确认和审计方式：确认必须在远程请求前发生；审计不保存正文或明文 token。

## 数据与迁移

K.0 无 schema 或数据变化。K.1 才能新增文档策略和 Provider 位置，并必须覆盖旧库升级、重复初始化、非法组合与
revision 失效。K.4 才能新增 grant 表和消费状态机。

## 验证

- 自动测试：匿名评测 fixture 的协议、分类覆盖、唯一 ID、虚构来源和安全字段检查。
- 手工验收：维护者能说明“本地命中不等于允许远传”，并能指出 explicit 仍是默认模式。
- 监控或日志：K.0 不新增运行日志。

## 回滚

删除本 ADR、评测说明和 fixture 即可回到 K.0 前状态，不涉及运行数据。已接受后的后续实现若改变核心决策，必须
新增 ADR 取代，不直接重写历史。
