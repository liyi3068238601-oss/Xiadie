# ADR-0048：两阶段跨会话历史回忆与显式优先启用

- 状态：Accepted
- 日期：2026-07-20
- 阶段：CTX.5
- 协议：`conversation-history-index-v1`、`conversation-history-score-v1-shadow`、`context-package-v1`

## 背景

遐蝶的会话用于整理话题，而不是人格边界。原始消息虽然完整保存在 SQLite，但新会话此前只能依赖长期
Fragment 等派生记忆，无法可靠回答“我以前问过什么”这类关于真实共同对话的问题。直接搜索并拼入所有
旧消息会污染当前聊天、浪费预算，也会让低价值旧问答错误进入长期记忆。

产品核心是陪伴、聊天和伴侣感，因此历史能力应让遐蝶自然想起真实过往，而不是把主界面变成检索系统。

## 决策

1. schema 44 为 session 标题、active 会话摘要和 message 正文建立本地可重建 FTS5 trigram 索引；新建、
   重命名、摘要激活/失效、消息变更和永久删除通过触发器同步。
2. 召回严格分两阶段：先选至多 6 个相关会话，再只在这些会话中选择少量消息，并扩展为完整
   user/assistant 轮次；单会话至多 2 轮、总计至多 4 轮。
3. 候选携带 session/message ID、时间、标题和 locator。ContextAssembler 再验证来源类型、完整轮次、
   当前会话排除和重复项，不能信任检索器直接给出的正文。
4. 跨会话历史拥有独立动态预算组件，不挤占当前用户消息与最近完整轮次；来源类型与当前会话、长期记忆、
   用户知识明确区分。
5. 默认模式为 `explicit_only`。明确询问过往时可注入；普通问答仅生成无正文 shadow 诊断，待固定评测集
   校准后才考虑自动启用。评分权重带版本，不作为不可变协议。
6. recall event 只记录 query SHA-256、计数、信号、权重版本和淘汰原因，不记录查询或召回正文。
7. 归档会话仍可召回；永久删除依赖既有 session 级级联删除摘要，并同步移除历史索引。新建会话和长期
   记忆开关均不清除、隔离或绑定历史索引。
8. 普通聊天界面不展示来源徽标、评分、数量或检索过程。后端只为明确来源询问保留真实 locator。

## 后果

- “12×8”无需污染长期记忆，但用户换会话后明确询问仍可从原始对话档案中找回。
- 普通陪伴聊天不会因尚未校准的历史权重突然带入无关旧话题。
- 本地索引可重建；删除与归档语义清晰，且不改 Fragment、Episode、Saga 或 Archivist。
- CTX.6 可在不改召回协议的情况下增加用户开关、重建入口和高级诊断。

## 验证

- 固定 `conversation-history-eval-v1` 覆盖数学原问、中文同义表达、代码符号/日期和 Blender 决定。
- 覆盖相关旧会话与较新无关会话竞争、归档/永久删除、新建会话、长期记忆开关独立性。
- 覆盖标题和 active summary 索引生命周期、完整轮次、来源多样性、locator 与无正文审计。
- 覆盖 ContextAssembler 独立预算和聊天主链路，只向模型注入选中的旧轮次。
- 全量回归：后端 484 项、前端 33 项、生产构建与 Electron 语法检查通过。
