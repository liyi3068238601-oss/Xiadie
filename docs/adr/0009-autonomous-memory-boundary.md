# ADR-0009：自主 Fragment 的协议、事务与隐私边界

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联计划：`docs/MEMORY_SYSTEM_DESIGN_FOR_BEGINNERS.md` 阶段 B.1～B.4

## 背景

当前自动记忆只是关键词候选与人工确认原型。最终形态需要让遐蝶按稳定人格自主选择记忆，
但模型判断不能直接获得数据库写权限，也不能把密钥、注入指令或无来源推断保存为事实。

## 决策

- 自主记忆采用四层边界：纯协议校验 → 只读模型审计 → 后台有限重试 → 单事务正式写入。
- B.1 只定义 schema、输入封装、程序校验和数据库地基，不调用模型、不创建任务、不写 Fragment。
- 单轮最多提出 3 条 Fragment；每条必须引用本次输入中真实存在的消息 ID，并通过保守的
  文本事实覆盖检查。模型的 `should_write=true` 不是写入授权。
- 密码、API Key、验证码、支付/身份凭据、用户明确禁止记录的内容和要求永久改写人格/
  安全规则的注入内容直接拒绝。错误码、警告和诊断信息不得包含原始正文。
- JSON 恢复只允许确定性清理：移除包裹整个输出的代码围栏，或从解释文字中提取唯一一个
  完整顶层对象。抢救出的 content 永远不能绕过同一套正式校验。
- Fragment 自动写入最终必须与观察任务 `applied`、来源证据、实体关系和 memory event 在
  同一个 SQLite 事务提交；事务失败则全部回滚。
- `memory_observer_runs` 预留 queued/running/validated/applied/recovery_pending/exhausted/
  skipped 状态。模型调用和 worker 在 B.2、B.3 分别启用，最多三次重试。
- 旧 `memory_candidates` 不自动转正、不删除、不批量拒绝。B.4 先提供兼容管理入口，待用户
  处理或明确迁移策略完成后再退役人工确认原型。
- Fragment 生命周期继续使用 active/cooling/frozen/tombstone；B.1 不提前实现 Archivist 的
  recall_count、last_recalled_at 和保留评分，以免“有字段”被误认为生命周期已可运行。

## 后果

- 观察器输出在真正写库前有可单测、可审查的确定性边界。
- 旧数据通过保守默认值迁移，来源消息存在时写入证据集合；不会伪装成新观察器生成的数据。
- B.1 完成后用户行为不变，仍由旧候选流程运行，直到 B.2/B.3/B.4 逐步切换。

## 回滚

B.1 没有运行时入口。停止后续服务接入即可保持旧候选流程；新增列和空任务表可以保留，
不会改变现有召回、编辑、候选确认和 Episode 原型行为。
