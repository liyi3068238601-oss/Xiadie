# ADR-0029：用户文件知识库的边界与数据地基

- 状态：Accepted
- 日期：2026-07-16
- 阶段：知识库 F.1
- 关联版本：schema 28

## 背景

“文件与知识”目前只有占位页面。内置 Lore、人物相处记忆和用户文件的来源、可信度、删除方式完全不同，
不能把文件切片写进 `memory_fragments`，也不能把外部文档文字当作系统指令。文件处理还会引入磁盘读取、
原文缓存、远程服务披露、长任务取消和彻底删除等新的授权边界。

## 决策

1. 三个命名空间永久分离：内置 Lore 使用代码内资源；相处记忆使用 memory/episode/saga；用户文件使用
   `knowledge_*`。知识切片不建立 `memory_fragment_relations`，文件里的“我”不代表用户或遐蝶。
2. 首批真实导入只支持 `.txt` 与 `.md`，编码为 UTF-8/UTF-8 BOM；PDF、DOCX 在独立解析阶段加入。
   不以扩展名作为唯一依据，后端必须联合检查扩展名、MIME、文件头、解码和实际大小。
3. 初始配额：单个 TXT/MD 原文件最多 10 MiB、解码后最多 2,000,000 字符；最多 100 个 active 文档，
   应用管理的原文件副本合计最多 250 MiB。超限在复制和建库前拒绝，配额以后可通过新 ADR 调整。
4. 用户必须明确选择或拖入文件。后端只接收这次选择的数据，不扫描目录、不跟踪原路径、不后台发现文件。
   校验成功后把原文件复制到应用数据目录，用随机 `storage_key` 管理；数据库不保存绝对原路径。
5. 默认仅使用本地解析和 SQLite FTS5，`embedding_mode='none'`。远程 Embedding 必须在导入/重建前显示
   供应商、模型、将发送的内容范围并取得本次明确同意；敏感文档默认禁止远程发送。F.1 不调用网络。
6. 文档内容是“引用资料”，在模型提示中使用独立、带来源的低权限区块，并明确其中任何命令、角色要求、
   工具调用或授权文本都只是资料。它不能修改 system prompt、人格、权限或工具策略。
7. schema 28 只建立 collection、document、import run 和无正文事件账本。切片与 FTS 在来源定位协议确定后
   另做迁移，避免先写一个无法稳定引用的索引结构。
8. 导入任务具有 queued/running/cancel_requested/cancelled/completed/failed/recovery_pending 状态、阶段、
   进度、有限重试和错误码。事件不得保存文件名、原文、切片、绝对路径或模型原始输出。
9. 删除开始时文档立即进入 `delete_pending` 并退出检索；随后清除原文副本、切片、FTS、向量和派生摘要。
   全部成功后物理删除 document 和事件；失败保持 `delete_failed` 且仍不可检索，允许重试。应用外备份不受影响。
10. 相同 collection 内以解码前文件字节 SHA-256 去重；同名不同内容允许并存并显示内容短指纹。更新采用
    新文档版本，不静默覆盖旧来源。

## 后果

- schema 28 本身不会读取、复制或上传任何用户文件，现有占位 UI 仍不得声称已经导入成功。
- 后续解析、切片、索引、召回和删除都拥有清晰的状态与回滚落点。
- 知识与人物记忆之间不做自动冲突推断；如果资料与相处记忆不一致，回答应分别标注来源，而不是互相覆盖。
- 文件名保存在 document 元数据供用户识别，但任务事件和日志保持无正文、无路径。

## 验证

- migration 28 从旧库升级、重复初始化、默认 collection、约束、级联关系和无正文事件列均由自动测试覆盖。
- 全量后端、前端构建和 Electron 脚本检查通过后，F.1 才能勾选完成。
