# ADR-0003：情绪与记忆观察共享来源和隔离协议

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联：情绪阶段一、记忆阶段 B

## 背景

情绪事件和记忆 Fragment 都引用聊天消息。为了节约模型成本，未来还可能由一次旁观模型调用同时产生情绪与记忆观察。如果没有统一来源和独立校验规则，一侧截断或失败可能污染另一侧。

## 决策

### 来源消息

- 消息 ID 继续使用 `db.new_id()` 生成的 16 位十六进制字符串。
- `source_session_id` 和 `source_message_id` 在时间漂移、手动重置等无消息事件中允许为空。
- 对话观察产生的情绪事件和记忆 Fragment 必须引用真实存在、且属于本轮输入集合的消息 ID。
- 消息删除使用 `ON DELETE SET NULL`；派生对象保留，但显示“来源不可用”，不得伪造引用。
- 隐私清除可以进一步移除派生内容，最小审计记录不得复制被清除正文。

### 合并观察响应

```json
{
  "affect": {
    "affect_delta": {},
    "relationship_delta": {},
    "reason": "",
    "confidence": 0.0
  },
  "memory": {
    "should_write": false,
    "items": []
  }
}
```

- 顶层只负责封装，不存在“整体通过”状态。
- 解析器独立提取并校验 `affect`，失败只进入情绪恢复流程。
- 解析器独立提取并校验 `memory`，失败只进入记忆恢复流程。
- 两侧使用独立事务；一侧数据库提交失败不能回滚另一侧已经合法提交的结果。
- 原始观察输出可以进入有期限、受保护的诊断记录，但不得直接成为正式记忆或系统提示内容。

## 后果

- 两个系统可以共享一次模型调用的固定开销，又不会共享失败域。
- 来源删除行为一致。
- 实现需要两个 schema 校验器、两个恢复任务类型和独立审计事件。

## 回滚

可以改为分别调用两个观察器；来源消息规范和各自校验器保持不变。
