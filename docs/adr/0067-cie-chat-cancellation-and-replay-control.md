# ADR-0067：CIE 聊天取消、阶段边界与短期幂等重放

- 状态：已接受并随 CIE.2 冻结
- 日期：2026-07-29
- 协议：`cie-cancel-control-v1`

## 决策

在 `cie_enabled` 总门后，为每次聊天请求使用彼此独立的 `chat_nonce` 与 `cancel_token`。后端维护单进程、有界 TTL 的活动请求和已完成重放表；阶段限定为 `retrieval → generation → persistence`，只有前两段接受取消。进入 persistence 后拒绝取消，让消息、引用及旧回复替换事务完整结束。

前端使用 `AbortController`，但只在后端明确返回 `accepted=true` 后中止读取；不能确认取消或已进入 persistence 时不武断断流。被取消的部分生成正文不持久化、不写日志。相同 `chat_nonce` 在五分钟窗口内重放同一权威终态，不再次生成或持久化。

## 边界

- CIE 关闭时，携带 CIE 请求控制字段的请求在消息写入前失败；前端把尚未持久化的 envelope 恢复为旧单消息输入草稿。
- 取消只影响活动聊天 LLM；CDS 对未开始低优先级任务的既有抢占契约不变。
- 用户原消息在生成前已经持久化；取消只丢弃未完成助手正文。补充消息作为新的原消息进入新请求，并重新执行知识预检、授权、KIG 来源快照与候选验证。
- 已进入持久化的回复保留；重新生成仍只在新回复成功写入的事务中替换旧回复。
- 当前 Electron 单进程架构不占用 Schema 81。幂等重放不承诺跨进程重启；若未来支持多 worker、崩溃恢复或长期取消审计，必须另立迁移和 ADR。

## 回滚

关闭 `cie_enabled` 即停止建立新控制请求；已活动请求仍可通过其不可猜测 token 协作取消。删除前后端 CIE.2 控制接线即可回到 CIE.1，数据库无迁移和用户数据转换。
