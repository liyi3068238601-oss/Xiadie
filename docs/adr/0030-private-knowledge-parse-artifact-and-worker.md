# ADR-0030：私有知识解析产物与可恢复 worker

- 状态：Accepted
- 日期：2026-07-16
- 阶段：知识库 F.3
- 关联版本：schema 29

## 背景

F.2 已把用户明确选择的 TXT/Markdown 安全复制到应用目录，但文档仍不能直接参与检索。解析可能被用户
取消、进程退出或损坏文件打断；如果把半成品正文写入数据库或提前标记为可用，后续切片和索引会看到不
一致的数据。正文、绝对路径和文件名也不应进入任务事件或诊断响应。

## 决策

1. 使用版本化、确定性的本地解析器。TXT/Markdown 都严格按 UTF-8/UTF-8 BOM 解码并统一换行为 `LF`；
   Markdown 只提取代码围栏之外的 ATX 标题。本阶段不切片、不索引，也不执行文档中的任何指令。
2. 统一后的全文和标题结构写入应用私有目录的随机键 JSON 中间产物。数据库只保存 artifact key、解析器
   版本、规范化哈希及字符/行/标题计数；公共 API 和事件不返回中间产物路径或正文。
3. 解析前重新计算应用内原始副本的 SHA-256，必须与准入时记录一致。失败、取消或校验不一致时不能留下
   新的解析产物，更不能产生可检索内容。
4. worker 串行认领 validation/copy/parsing 阶段任务，最多尝试三次并使用指数退避。运行任务超过陈旧阈值
   后转入 `recovery_pending`；已请求取消的陈旧任务直接完成取消。
5. 运行中取消采用协作检查点。解析前后都会检查 `cancel_requested`；已完成解析但尚未切片的取消会删除
   私有解析产物，但保留用户导入的原始副本，完整删除语义仍由 F.7 实现。
6. 解析成功只表示本阶段完成：任务转为 `queued/chunking`、进度 45%，文档仍保持非 indexed 状态。F.4
   必须从私有中间产物原子生成稳定切片后才能继续推进。
7. 任务事件只记录阶段、状态、错误码、尝试次数和计数。正文、文件名、绝对路径、模型输出均不得进入事件。

## 后果

- 进程中断和重试不会让半套解析结果进入检索；同一输入及解析器版本产生相同的规范化内容和哈希。
- 私有中间产物会暂时占用额外磁盘空间，F.7 删除闭环必须同时清除原文件、解析产物、切片和索引。
- 文件页可以诚实展示解析完成但等待切片，而不会把“解析成功”误报为“知识可用”。

## 验证

- 自动测试覆盖换行与标题确定性、代码围栏、取消检查点、取消后清理、原始哈希篡改、有限重试、陈旧恢复、
  schema 29 升级保真、并发配额以及 API/事件隐私。
- 后端全量 269 项、前端 19 项、生产构建和 Electron 主进程语法检查通过后，F.3 才勾选完成。
