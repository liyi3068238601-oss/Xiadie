# ADR-0033：受约束的知识对话召回与可验证引用

- 状态：Accepted
- 日期：2026-07-16
- 阶段：知识库 F.6
- 关联版本：schema 32

## 背景

F.5 已能返回带稳定 locator 的真实本地切片，但直接把正文拼入 system prompt 会扩大提示注入风险；只要求模型
“附来源”也无法阻止它生成不存在的文档或定位。流式回答还必须在不破坏现有聊天体验的前提下完成最终校验。

## 决策

1. 第一版只以“知识库、文档、文件、根据资料、引用来源”等显式资料意图确定性触发，不增加模型分类调用，普通
   陪伴对话不查询用户文件。无结果不注入空资料块，也不虚构回答证据。
2. 命中按当前 FTS 排名逐条保留 locator，不把相邻切片合并成一个引用。固定前导安全说明和 JSON 记录一起纳入
   1200 token 保守预算；知识、Lore、相处记忆分别计量。
3. 正文仅作为低权限、不可信 JSON 引用数据进入提示。内容中的命令、角色、安全策略、授权和工具请求不可执行。
4. 本轮允许引用集合使用临时 `K1…Kn`。流结束后，后端只接受允许集合中的 `[资料:Kx]`；未知标记替换为
   `[资料引用无效]`。只有模型实际使用的允许引用与助手消息在同一事务中写入。
5. schema 32 审计仅保存查询 SHA-256、触发原因、候选/注入数量和三类 token 计数，不保存查询或正文。引用保存
   文件名与 locator/哈希快照，不保存第二份正文。
6. 点击引用时必须从当前 chunk 读取正文，并复核 document= indexed、collection=active、索引版本、chunk ID、
   保存哈希以及当前正文重新计算的 SHA-256。任一不符返回 410；定位快照只用于说明旧来源，不能冒充真实原文。
7. 原始 delta 可以继续流式显示；`done` 后前端重新读取已校验落库内容，因此伪引用不会成为正式消息。

## 不采纳或延期

- 不采纳 review 中与实际实现不符的“外部内容 FTS、30 条结果、现成搜索 UI、已实现 DELETE”描述。
- 不采用模型意图分类器，避免额外成本、延迟和不确定触发。
- 不合并连续 chunk，因为会模糊各自 locator。Embedding provider/向量降级接口留到 F.8，完整删除状态机留到 F.7。

## 验证

- 覆盖显式/普通触发、无结果、token 预算、提示注入文本隔离、允许/伪造引用、无正文审计、消息引用持久化及
  正文变化后的 410。
- 前端契约验证引用按钮和真实来源 API；全量后端、前端测试、生产构建及 Electron 检查通过后才勾选 F.6。
