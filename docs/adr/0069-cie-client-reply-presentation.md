# ADR-0069：CIE 客户端回复节奏与权威正文替换

- 状态：已冻结（独立 Review 0 P0 / 0 P1）
- 日期：2026-07-29
- 协议：`reply-presentation-v1`
- Schema：81（CIE.4 不占用 82）

## 决策

CIE.4 只在 `cie_enabled` 开启时增加客户端展示缓冲。它接收服务端原始 delta，按代码围栏、行内代码、URL、Markdown 链接、数字和引号感知的安全边界排队，以固定短间隔逐段显示；所有单元都是原字符串切片，不增加、删除、重排或改写字符。

服务端 `final`/兼容 `done.content` 继续是唯一权威正文。终态到达后，客户端取消剩余计时器并以权威正文整体替换预览，不把缓冲内容再次追加，因此节奏层不能改变持久消息或产生重复发送。用户新消息被服务端接受为生成取消后、会话切换、组件卸载、请求失败或中止时，未展示单元直接丢弃。

独立 Review 后补强：收到 final 并替换正文的同一次状态更新立即标记 `completed`，避免 final 与 done 间隔较长时仍显示整理状态。控制 state 继续保存冻结的协议枚举，中文只在渲染边界映射。

## 输入状态

后端冻结的 `retrieval / generation / persistence / completed` 控制阶段不直接暴露为技术术语。客户端映射为“正在准备回复 / 正在组织语言或继续回应 / 正在整理这次回复 / 回复完成”，只影响辅助状态文字，不修改模型正文。

## 边界

- CIE 关闭时继续逐 delta 原样显示，保持 CIE.0 fallback。
- CIE.4 不调用模型、不生成表达计划，也不修改 EAP 冻结的 `expression-plan-v1`；当前不需要提出 `expression-plan-v2`。
- 展示单元并非语义句子或可持久对象，不进入消息、Memory、Knowledge、日志或 Schema。
- Markdown 在中间帧仍可能处于“尚未接收完整后文”的自然流式状态，但安全切分不会把完整代码围栏拆成不同展示单元；最终渲染始终来自权威正文。

## 回滚

关闭 `cie_enabled` 或移除 `ReplyPresentationBuffer` 接线即可恢复逐 delta 展示。没有数据库迁移、用户数据转换或服务端协议回滚。
