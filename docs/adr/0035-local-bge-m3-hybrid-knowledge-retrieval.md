# ADR-0035：本地 BGE-M3、格式注册表与混合知识检索

- 状态：Accepted
- 日期：2026-07-16
- 阶段：知识库 F.8

## 背景

F.1～F.7 已完成用户知识的安全准入、确定性文本解析、稳定 locator、contentless FTS、对话引用与删除闭环。
项目目录现有一份 BGE-M3 量化 ONNX 模型；最新 review 建议把 PDF/DOCX、向量版本、降级策略和删除同步作为
F.8 总验收的一部分。向量不能成为删除旁路，也不能让模型缺失或推理失败拖垮已有 FTS。

## 决策

1. 解析改为扩展名注册表。TXT/Markdown 继续确定性解析；PDF 使用 `pypdf` 提取真实页面并保存 page span；
   DOCX 使用 `python-docx` 提取标题、段落和表格，但不伪造 DOCX 不具备的稳定页码。扫描 PDF 不做 OCR，
   无可提取正文时返回明确错误。
2. PDF 校验文件头；DOCX 在解析前校验 ZIP 条目数、解压总量、压缩比、必需成员与越界路径，限制容器型输入风险。
3. `EmbeddingProvider` 是可替换边界。当前实现只启用本地 `BAAI/bge-m3` 量化 ONNX 的 dense 输出：CLS pooling、
   L2 归一化、1024 维、512 token 截断。该 ONNX 不暴露 sparse/ColBERT 输出，因此不宣称支持它们。
4. 远程 provider 默认拒绝；没有“本次明确同意”对象时绝不发送正文，当前也不配置任何远程向量服务。
5. FTS 与向量分别版本化。`auto` 模式使用 reciprocal-rank fusion 合并 FTS 和 dense 结果；向量模型、运行依赖、
   建库或查询失败时自动保留完整 FTS 路径。`fts`/`vector` 模式仅用于显式诊断和测试。
6. 每个 chunk 的向量与 document、内容哈希、provider、模型、版本和维度绑定。向量批次先计算、后在单事务中替换；
   提交前重新核对文档状态和 chunk 哈希，防止重建期间写回陈旧结果。
7. 重建和删除请求一经接受，立即清除向量并跳过活动向量任务；物理删除再次清理并依赖外键级联兜底。
   向量不可用或已移除时，文档仍按既有状态控制 FTS 可见性。
8. 桌面打包把外层 `bge-m3` 复制到临时 model stage，再作为只读 resource 随安装包分发；模型本体不进入 Git。

## 结果

- PDF 引用可以携带真实页码，DOCX 保留结构但诚实显示无页码。
- 本地语义检索不上传正文，且不会成为删除、重建或失败恢复的旁路。
- 安装包会增加约 543 MiB 模型资源；冷启动首次加载 ONNX 有额外内存与时间成本，provider 因此采用惰性加载。
- 审计长期保留/归档策略不在 F.8 临时决定，留给统一生命周期阶段设计。

## 验证

- 真实 BGE-M3 冒烟：CPU 加载和推理成功，输出有限的归一化 `[batch, 1024]` dense 向量。
- API E2E：PDF 导入 → 真实页解析 → 切片 → FTS → dense → hybrid 检索 → 立即退出召回 → 物理删除。
- 回归覆盖损坏 PDF/DOCX、模型失败 FTS 降级、版本绑定、重建/删除同步和远程逐次同意边界。
