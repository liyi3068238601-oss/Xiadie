# ADR-0045：对话上下文、会话摘要与长期记忆边界

- 状态：Accepted
- 日期：2026-07-19
- 决策者：遐蝶项目
- 关联版本/任务：`CONVERSATION_CONTEXT_AND_SUMMARY_PLAN.md` CTX.0
- 取代：无
- 被取代：无

## 背景

当前聊天主链已经保存完整 `messages`，并使用临时 `context_budget.py` 估算和裁剪当前会话历史。项目同时存在
Fragment、Episode、Saga、Memory Observer 与 Archivist 等长期记忆能力。滚动会话摘要和跨会话历史回忆尚未
实现，如果不先固定职责边界，后续容易把 Episode/Saga 当作上下文压缩摘要，或为了节省 token 改写长期记忆。

## 决策

1. `messages` 是用户与遐蝶实际对话的原始档案和逐字权威。上下文裁剪、摘要生成和检索不得覆盖或改写原消息。
2. 会话滚动摘要是可重建的派生数据，只服务于单次模型上下文组装；它不是真实原话，也不是长期记忆。
3. 跨会话历史回忆从原始消息和会话摘要中按需选择内容，用于回答“我们具体谈过什么”。
4. Fragment、Episode、Saga 及其 Observer、Consolidator、Archivist 继续作为独立的长期记忆系统；本专项只通过
   现有只读 digest 接口消费，不修改其 schema、写入、纠错、生命周期或 UI。
5. ContextAssembler 是唯一允许组合系统提示、当前消息、最近原文、滚动摘要、历史召回、长期记忆 digest、Lore
   与知识引用的边界。各来源必须独立计量并受当前模型真实窗口约束。
6. 普通聊天不展示检索、评分、摘要版本或来源卡片。内部保留不含正文的定位和预算诊断；只有用户主动询问来源时，
   才用自然语言解释并按需定位原会话。
7. 本地会话档案不设置固定轮数上限。单次模型请求的应用上限为 1,000,000 tokens，同时不得超过已验证的模型窗口。

## 备选方案

### 方案 A：把 Episode/Saga 直接作为滚动摘要

- 优点：可复用现有摘要字段。
- 缺点：经历叙事与上下文压缩目标不同，容易污染当前回答并破坏长期记忆生命周期。
- 未采用原因：职责混淆，回归风险过高。

### 方案 B：继续向模型发送当前会话全部历史

- 优点：短会话实现简单。
- 缺点：成本和延迟随会话增长，最终会超过模型窗口，并挤压安全规则、当前消息和输出空间。
- 未采用原因：不能支持长期陪伴对话。

### 方案 C：使用固定最近 N 轮

- 优点：容易实现和预测。
- 缺点：不同模型和消息长度差异巨大，固定轮数既可能浪费窗口，也可能丢失关键语境。
- 未采用原因：不符合动态模型能力和不限本地历史的产品目标。

## 后果

### 正面后果

- 长期记忆系统可继续稳定运行，上下文施工不会借机重构它。
- 原始对话、派生摘要和长期记忆分别具有清晰权威来源。
- 后续预算、摘要和历史召回可以独立测试、删除与重建。
- 用户获得自然连续的陪伴体验，而不是知识库式检索界面。

### 代价与限制

- 需要新增 ContextAssembler、模型能力表、摘要派生表和历史检索索引。
- 必须维护各来源的 token 预算、失效传播与无正文诊断。
- 在 CTX.1～CTX.5 完成前，当前临时裁剪缺陷仍然存在。

## 安全与隐私

- 权限等级：本地 S0 读取与派生；远程模型传输继续服从现有 Provider 和知识授权边界。
- 涉及的数据：对话原文、派生摘要、长期记忆只读摘要和上下文计量元数据。
- 是否访问网络：ADR 本身不新增网络访问；实际聊天沿用用户配置的 Provider。
- 是否产生外部副作用：否。
- 用户确认和审计方式：普通聊天不展示技术审计；内部诊断不得保存正文、摘要正文、密钥或模型原始输出。

## 数据与迁移

- 当前 schema：41。
- 下一迁移编号：42，预留给 `conversation_summaries` 及其事件表；CTX.0 不执行该迁移。
- 兼容旧数据的方法：原 `messages` 和长期记忆表保持不变，派生摘要可从原消息重建。
- 失败恢复方法：摘要或检索失败时回退到受硬预算保护的最近原文，不修改原消息和长期记忆。

## 验证

- 自动测试：CTX.0 固定临时预算器的已知失败基线；CTX.1 起逐项关闭预期失败。
- 手工验收：核对普通聊天不出现摘要、召回和 token 工程信息。
- 监控或日志：只记录组件估算量、模型窗口来源、裁剪数量和稳定错误码，不记录正文。

## 回滚

CTX.0 仅增加文档、基线脚本和测试，不改变运行行为，可直接移除新增文件回滚。后续数据迁移必须另行定义回滚。
