# ADR-0031：稳定知识切片与来源定位协议

- 状态：Accepted
- 日期：2026-07-16
- 阶段：知识库 F.4
- 关联版本：schema 30

## 背景

F.3 产生了经过校验的私有解析 artifact，但 FTS、引用和删除都需要稳定的最小文本单元。如果切片依赖随机
窗口、伪造页码或在多次事务中逐条可见，同一来源会得到漂移的引用，并可能在失败时留下半套数据。

## 决策

1. `knowledge-structure-chunker-v1` 只读取 `knowledge_parse_artifacts` 指向的私有 JSON，不重新解释原始文件。
   读取后复核解析器版本、规范化正文 SHA-256 和字符数，并从正文重新计算标题结构逐项比对。
2. Markdown 把 ATX 标题视为结构边界，并继承当前标题层级路径；TXT 与 Markdown 都优先使用空行段落边界。
   目标大小为 800 字符、硬上限 1200 字符，不使用重叠窗口，避免后续检索重复计分和引用重叠。
3. 超长段落从目标位置向前至硬上限寻找中英文句末；找不到时回看目标位置之前的句末，仍找不到才在
   1200 字符处硬切。协议参数或算法改变必须提升 chunker 版本并重建，不可静默改变既有定位。
4. locator 坐标固定为：`ordinal` 从 0 开始；段落和行号从 1 开始且首尾均包含；字符起点从 0 开始、终点
   为开区间。`heading_path_json` 是从顶层到当前节的字符串数组；内容哈希为切片 UTF-8 字节 SHA-256。
5. `page_start/page_end` 是统一 locator 的可空占位。TXT/Markdown 没有真实分页，必须保持 NULL；未来
   PDF/DOCX 解析器只有在来源确实提供页码时才可填写。
6. chunk ID 由 document ID、chunker 版本、ordinal、字符范围和内容哈希确定性生成。相同 document、解析
   artifact 和协议版本重复切片，ID、顺序、正文、哈希和 locator 必须完全相同。
7. worker 在内存完成整份切片后，以一个 `BEGIN IMMEDIATE` 事务删除旧切片、插入全套新切片、更新文档
   计数并把 run 推进到 `queued/indexing`。事务失败全部回滚；F.4 不设置 `indexed_at`，不把切片误报为可检索。
8. 切片循环保留协作取消检查点并复用每阶段三次指数退避。取消删除 chunks、解析 artifact 和派生元数据，
   但保留 F.2 原文件；document 物理删除通过外键级联清除 chunks，完整删除闭环仍由 F.7 管理。
9. chunk 正文不进入任务事件、日志或文档列表 API。阶段事件只记录尝试次数和最终 chunk_count；意外异常
   日志只记录异常类型，不输出底层消息、正文或路径。

## 后果

- F.5 可以在稳定 chunk 表上原子建立 FTS，F.6 可以直接复用同一 locator 生成可验证引用。
- 无重叠切片减少重复召回，但跨切片上下文需由 F.5 相邻 ordinal 扩展策略解决，不能改变原始 locator。
- 切片正文进入本地 SQLite，仍只在应用本地使用；任何远程 Embedding 继续受 ADR-0029 的逐次披露约束。

## 验证

- 自动测试覆盖 Markdown 标题路径、TXT 段落、短行列表、中英文、句末与硬边界、确定性 ID/定位、协作
  取消、artifact 篡改、事务整批回滚、日志净化、schema 升级和级联删除。
- 后端全量 282 项、前端 20 项、生产构建和 Electron 主进程语法检查通过后，F.4 才勾选完成。
