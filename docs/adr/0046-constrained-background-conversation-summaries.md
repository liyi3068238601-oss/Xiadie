# ADR-0046：受约束的后台会话摘要

- 状态：Accepted
- 日期：2026-07-19
- 阶段：CTX.3

## 背景

CTX.2 只建立了可追溯摘要账本。遐蝶仍以陪伴、聊天和长期关系连续性为核心，因此摘要必须在后台安静
工作：不能阻塞聊天，不能把技术面板变成主体验，也不能把不可信对话、密钥或模型幻觉写成正式经历。

## 决策

1. 使用 `conversation-summary-v1`。模型只输出抽取式主题、连续性、决定、纠正、开放事项和必要实体；
   正文由通过校验的来源原句确定性拼接。
2. 每条决定和纠正都必须引用真实 message ID，并由用户原话及相应语义线索支撑。纠正显式指向被替代
   来源，激活前删除旧决定，保留纠正证据。
3. 输入在模型调用前净化密钥和敏感串；检测到提示注入时隔离整条指令消息。所有输出字段再次执行来源
   与敏感内容校验。
4. JSON 结构错误最多进行一次只修结构的受限修复。模型不可用、来源变化或校验失败时保持无摘要，
   不创建抽取式或模型式虚构回退。
5. 摘要模型支持 current/dedicated 配置，并公开解析后的 Provider、模型、执行位置与位置 revision。
   摘要模型默认可处理生成摘要所需的历史对话；入队时仍绑定 Provider 位置，之后位置或 revision 变化会使任务失败。
6. 聊天成功持久化后只入队并唤醒 worker，不等待摘要生成。摘要失败、指标失败和入队失败均不能改变已
   完成的聊天结果。
7. 第一版采用增量生成，并在每 5 个 active revision 后从连续原文全量重建。增量只合并已验证旧结构与
   新增来源，不能引入没有来源的漂移。
8. schema 43 在 run 上保存位置绑定、生成模式、输入/输出字符、usage、耗时和修复标记；只读诊断计算
   压缩比，不公开摘要正文、模型原始输出或租约令牌。
9. 普通陪伴聊天界面不增加常驻摘要展示。开发诊断继续通过后端只读来源范围、状态、计数和指标完成。

## Review 建议处理

- 采纳 CTX.2 strict review 的 5 条 P0：协议证据、注入防护、敏感串净化、Provider 切换边界和聊天故障隔离。
- N20/N21 原按用户决定留到计划末尾；用户在本阶段重新授权后，确认是独立低风险修复，已一并完成。
  用户未提交的 `knowledge-recall-eval-v3-search-v2.md` 保持不变。

## 后果

CTX.3 只生成可验证派生摘要，仍不影响普通聊天回答。CTX.4 才能在硬预算与来源去重约束下消费 active
摘要。阶段完成后需接受独立 review；在 review 通过前不进入 CTX.4。
