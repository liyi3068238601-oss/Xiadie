# ADR-0044：知识系统总验收与 Windows 未签名构建边界

- 状态：接受
- 日期：2026-07-19
- 关联：ADR-0029～ADR-0043、`KNOWLEDGE_SYSTEM_OPTIMIZATION_PLAN.md` K.9

## 背景

K.0～K.8 已分别实现自然召回、远传策略、一次性授权、确定性重排、知识/记忆隔离和审计生命周期。K.9
需要固定“哪些证据足以宣告知识系统阶段完成”，并保证普通 Windows 账户能冻结和打包包含本地 BGE-M3 的应用。

electron-builder 默认会在没有签名证书时仍下载 winCodeSign 来编辑可执行文件元数据。该工具包包含 macOS
符号链接；未启用 Windows 开发者模式、也没有创建符号链接权限的普通账户会在解压时失败，尽管应用资源已经复制完成。

## 决策

1. K 系列完成必须同时满足模式、Provider 位置/文档策略、授权状态、安全降级、删除重建、知识/记忆隔离和发布产物矩阵；单一单元测试或界面截图不能替代总矩阵。
2. 模型、Provider 位置、召回模式、策略 revision、查询计划或来源指纹任一变化，都使已有 pending/issued grant 失效；失败发生在写入用户消息和调用在线模型之前。
3. BGE-M3 继续位于 Git 仓库外，由构建脚本暂存进安装资源。源、暂存和安装资源中的量化 ONNX 必须匹配代码锁定的 SHA-256；正文不发送给远程 embedding。
4. 当前无证书的个人开发构建设置 `win.signAndEditExecutable: false`，使普通 Windows 账户不依赖 winCodeSign 解压权限。此设置不表示产物已签名，也不消除 SmartScreen 提示。
5. 获得正式代码签名证书准备公开发布时，必须重新启用可执行文件编辑/签名，补做签名、安装、卸载、升级和 SmartScreen 验收；不得沿用本 ADR 的未签名发布边界宣称正式发布就绪。
6. 冻结后端必须以无控制台进程实际启动，验证本地 API、数据目录、local-only embedding 和模型指纹；Electron 必须完成生产前端、unpacked 资源和 NSIS 安装器构建。

## 结果

- 普通开发账户可以生成可运行的未签名个人测试包，不再因无关的 macOS 符号链接权限失败。
- 构建新增可重复的冻结后端冒烟和发布资源校验脚本；一键 Windows 构建在生成安装器后自动执行资源校验。
- 正式签名、安装升级和可再分发 Live2D 资产仍是发布阶段任务，不属于知识系统 K 系列完成条件。
