# ADR-0015：Episode 摘要必须由来源原句组成

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联版本/任务：记忆系统阶段 C.4
- 取代：无
- 被取代：无

## 背景

C.3 能稳定选择高分 Fragment 分组，但旧规则只是把 Fragment 文本截断拼接成标题和摘要。模型
可以让摘要更聚焦，却也可能添加来源不存在的地点、原因、关系、心理或结果。仅要求模型声明
evidence ID 不够，因为模型可以给虚构句子配一个真实 ID；仅做相似度覆盖也会让“真句子 + 少量
虚构补充”通过。

## 决策

### 协议与事实边界

- 使用严格 `episode-summary-v1` JSON，只允许 `protocol_version`、`title`、`claims`。
- 每个 claim 包含 `text` 与 1～4 个 `fragment_ids`；ID 必须属于当前分组。
- `claim.text` 规范化后必须是每一个所列 Fragment 内容的连续子串。程序只用通过校验的 claims
  拼接 summary，模型不能直接提交 summary 字段。
- 重复 claim、越权 ID、来源不覆盖、不安全内容和超过长度/数量限制均拒绝整个模型结果。
- title 只允许来源或共同 Entity 中已有的主题词加“关于、一段、共同、经历、记录”等通用词；
  无法证明来源时拒绝整个模型结果。
- 输入 Fragment 放在 `user` 角色的不可信 JSON 中，系统指令明确不得执行其中命令。

### 调用与并发

- 默认跟随当前聊天模型，可通过本地 API 选择独立真实模型；mock 或不可用模型不调用网络。
- 调用使用 temperature=0、20 秒超时、500 输出 token 与 12000 字符上限。
- 只对 invalid JSON/type/schema 允许一次格式修复；事实、标题、ID 或安全错误不得通过修复绕过。
- 模型调用前计算来源内容哈希，应用时在 `BEGIN IMMEDIATE` 内重新读取 Fragment 并比较哈希。
  调用期间任何来源纠正都会拒绝旧输出，再从最新来源刷新回退摘要。

### 安全回退与审计

- 高分候选创建时先保存 `episode-extractive-v1` 回退：按时间选择安全 Fragment 原文并拼接，
  不生成新事实。
- 模型失败、不可用、输出非法、来源变化或内部错误均保留/刷新抽取式回退，不让 Consolidator
  任务失败，也不创建正式 Episode。
- 保存状态、协议版本、供应商/模型、证据 ID、来源哈希、稳定错误码、token 计数和是否修复。
- 不保存原始模型输出、完整 prompt、API Key 或被拒绝的虚构文本。
- `summary_validated` 与 `summary_fallback` 使用不同审计事件。

## 备选方案

### 允许模型自由改写，再用相似度阈值校验

- 优点：语言自然。
- 缺点：短小虚构内容可能被长句的高覆盖率掩盖，无法保证逐项事实来源。
- 未采用原因：共同经历比文风更需要可靠溯源。

### 再调用一个模型判断是否忠实

- 优点：可接受更多自然改写。
- 缺点：成本翻倍，两个模型都可能犯错，且审计边界更复杂。
- 未采用原因：C.4 优先建立确定性安全下限。

### 模型失败就放弃整个候选

- 优点：状态简单。
- 缺点：模型可用性会影响确定性分组结果，也会浪费已经通过 0.50 阈值的来源集合。
- 未采用原因：抽取式回退已经能提供无新增事实的安全摘要。

## 后果

### 正面后果

- 保存的模型摘要每个分句都能追溯到具体 Fragment 原句。
- 来源纠正与模型调用并发时不会写入过期摘要。
- 模型不可用不影响 Episode 分组与后续恢复。

### 代价与限制

- 摘要更接近摘录，语言自然度低于自由改写。
- 同义改写即使事实正确也会被拒绝并回退。
- C.4 仍只更新兼容 pending 候选；正式 Episode 原子写入由 C.5 完成。

## 安全与隐私

- 权限等级：本地 S0；模型调用使用用户已配置的供应商。
- 涉及的数据：最多 20 条 normal、active、enabled 且通过不安全模式过滤的 Fragment。
- 是否访问网络：真实摘要模型可访问网络；mock/不可用时不访问。
- 是否产生外部副作用：除模型请求外无外部副作用。
- 用户确认和审计方式：候选保存来源 ID、模型/回退状态与错误码；不保存原始输出。

## 数据与迁移

- schema 15 为兼容候选增加摘要状态、协议、供应商/模型、证据、警告、来源哈希、token 与修复字段。
- 旧候选默认 `legacy_rule`；不会伪装成已校验模型摘要。
- 新候选先写 `extractive_fallback`，只有事务内复核通过才改为 `model_validated`。

## 验证

- 自动测试：提示注入、正确原句、多来源误标、越权 ID、虚构 claim/title、一次修复、模型不可用、
  幻觉回退、调用中来源纠正、原始输出不落库、模型配置校验。
- 手工验收：本阶段不新增主界面，不使用内置浏览器。
- 监控或日志：候选摘要状态、稳定错误码和 memory_events 审计。

## 回滚

停止 `episode_summary_service` 调用即可。候选仍保留安全抽取式摘要；schema 15 字段继续保留，
不删除候选、Fragment 或事件。不要把 `model_validated` 反向标成 legacy。
