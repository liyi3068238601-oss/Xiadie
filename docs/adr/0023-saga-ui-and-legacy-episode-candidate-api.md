# ADR-0023：Saga 正式界面与旧 Episode 候选 API 退役边界

- 状态：已接受
- 日期：2026-07-16
- 阶段：记忆系统 D.6

## 背景

阶段 C 已把 Episode 从人工确认候选改为后台自动整理，阶段 D 已把正式 Episode 继续整理为 Saga。D.6
需要提供正式 Saga 界面，并决定旧 `episode-candidates` API 是否可以删除。当前主界面不再展示 Episode
候选确认，但后台排队仍复用 `/api/episode-candidates/generate`，后端回归测试、旧 pending 数据和兼容
接受路径仍依赖其余端点。

## 决定

1. 记忆页展示最近 100 条 Saga；真实数据规模证明需要前，不增加游标分页。
2. 界面只展示正式 Saga，不展示候选确认。列表和详情提供状态文字、当前阶段、Episode 时间线、来源
   Fragment/原对话入口、摘要协议与来源指纹、Entity、纠错记录和最近事件。
3. 内容纠错、来源纠错与生命周期写入都携带 `expected_revision`。409 冲突时刷新详情、关闭旧编辑器并
   要求用户重新确认；客户端不得自动重放有副作用的请求。
4. 来源纠错后使用当前 Episode 重建安全抽取式摘要。现有模型摘要协议绑定候选和整链哈希，在建立
   正式 Saga 专用重生成任务与审计协议前，不伪装成同步“重新生成”端点。
5. 关系 delta 建议保持只读内部审计状态。D.6 不增加消费、应用或手动改关系值的按钮。
6. 删除前端未使用的候选列表、接受和拒绝客户端方法；保留后台生成方法。
7. 暂时保留后端候选表和兼容 API，不迁移或删除历史数据。

## 后端退役条件

只有以下条件全部满足，才能另写删除迁移和 API 退役 ADR：

- 支持期内数据库已没有必须由兼容路径处理的 pending/accepted/rejected 历史候选；
- 桌面端、启动器、worker、测试和发布版本均不再调用候选列表、接受或拒绝端点；
- 后台 Episode 整理拥有不带“candidate”兼容语义的新排队端点，且至少经过一个稳定发布周期；
- 数据迁移明确保留正式 Episode 的 `candidate_id` 审计来源，不破坏既有来源链；
- 旧客户端调用时能收到明确版本错误，而不是静默 404 或丢失数据。

## 验证

- 前端契约测试保证 Saga 正式界面不出现候选接受/拒绝流程。
- 端到端测试覆盖 Fragment→Episode→Saga、追加、可信完成、恢复、来源纠错和 tombstone。
- 全量后端、前端、生产构建与 Electron 语法检查通过后，阶段 D 才能完成。
