# ADR-0006：观察模型调用、候选审计与恢复入队

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联计划：`docs/AFFECT_AND_RELATIONSHIP_SYSTEM_PLAN.md` 阶段 2.2

## 背景

ADR-0005 已定义模型输出的安全协议，但尚未决定真实调用如何幂等、失败如何与聊天隔离、哪些数据可以进入审计，以及进程中断后如何发现未完成任务。

## 决策

- 观察调用发生在助手回复成功持久化之后，重新生成不视为一轮新互动。
- 唯一幂等键为 `affect-observer-v1:{assistant_message_id}`。
- `affect_observer_runs` 保存来源消息、模型、状态、净化候选、稳定错误码、字符/token 计数和恢复时间。
- 原始失败输出、供应商异常正文、API Key 和请求头不进入数据库及 SSE。
- 只有通过 ADR-0005 校验的结果可以保存为 `candidate`；本阶段 candidate 不应用到状态。
- 网络、模型和协议失败进入 `recovery_pending`。进程中断留下的 `running` 超过两分钟也转入恢复队列。
- 单次调用最多输出 500 tokens、20 秒超时，并有输入与输出字符硬上限。
- mock 或没有真实服务地址时记录 `skipped`，不使用演示模型伪造情绪判断。
- 所有异常由观察服务入口吸收；聊天回复、fallback 状态和 SSE done 不依赖观察成功。

## 后果

- 每条回复最多产生一条观察记录，并发请求不会重复计费。
- 能估算调用成本和失败率，而不需要保存不可信原始失败文本。
- 当前观察仍与聊天完成链串行，且复用聊天模型；可靠后台执行、独立轻量模型和有限重试执行留到下一阶段。
- 在候选应用功能完成前，真实观察不会改变任何情绪或关系数值。

## 回滚

停止调用 `observer_service.observe_turn` 即可。迁移 8 的审计表与情绪状态表分离，保留或清空观察记录都不会影响会话回复和现有 affect 状态。
