# ADR-0047：统一 ContextAssembler 与受验证摘要注入

- 状态：Accepted
- 日期：2026-07-20
- 阶段：CTX.4
- 协议：`context-package-v1`、`context-budget-v1`、`conversation-summary-v1`

## 背景

CTX.1 已能在模型调用前实施硬预算，CTX.3 已能在后台生成有来源边界的会话摘要，但聊天入口仍由
`main.py` 直接拼接人格、记忆、Lore、知识和全量会话候选。若直接把摘要追加进去，会造成同一旧消息以
“摘要 + 原文”重复占用预算，也无法在 regenerate、来源变化或半轮边界下证明摘要仍有效。

产品核心是陪伴、聊天和伴侣感。用户需要感受到对话自然延续，而不是看到摘要修订号、token 或内部推理。

## 决策

1. 新增纯编排模块 `context_assembler.py`。它不读取数据库、不调用摘要服务、记忆或知识检索器，只接收
   调用方已经取得的结构化候选。
2. active 摘要在使用前重新验证：状态、协议、起止 message ID、连续 user/assistant 完整轮次、消息数、
   source hash，并且不得覆盖当前用户消息。滚动摘要必须从会话首轮连续覆盖。
3. 摘要通过后，其覆盖的旧原文不再进入 ContextPackage；source_end 之后的消息仍作为最近原文参与硬预算。
4. 摘要不存在、失效、来源变化、边界落在半轮或 regenerate 排除了来源消息时，不使用摘要，直接复用
   CTX.1 的完整轮次安全裁剪，绝不恢复为全历史发送。
5. 摘要、现有长期记忆 digest、用户知识和 Lore 使用独立限额；1M 仅是能力边界，不是填充目标。
6. `main.py` 保留候选读取、授权与副作用编排，不再构造最终 system prompt。记忆注入审计改变实际 digest
   时，重新调用 ContextAssembler，确保实际请求和 meta 一致。
7. SSE meta 只保留 revision、覆盖数、最近原文轮数和组件 token 计数，不含正文。普通前端不新增展示。

## 后果

- 长会话在存在可信摘要时可保留早期决定，同时避免重复携带覆盖原文。
- 摘要不可用不会破坏聊天，也不会绕过硬预算。
- 原始 messages 从未删除；摘要只是请求时的派生连续性组件。
- CTX.5 可在相同 ContextAssembler 上增加独立的跨会话召回预算区，不需要修改长期记忆内部实现。

## 验证

- 5、20、100、500 轮合成会话均满足硬预算。
- 半轮边界、source hash 变化、缺失摘要均拒绝摘要并安全裁剪。
- 覆盖原文不重复，source_end 后完整轮次保留。
- 长知识、长记忆、长 Lore 与长用户输入并存仍满足窗口不变量。
- regenerate 成功使覆盖 revision 失效；失败保持 active；生成中新增消息不污染当前 revision。
- 后端 469 项、前端 33 项、生产构建与 Electron 语法检查通过。
