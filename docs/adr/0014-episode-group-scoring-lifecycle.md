# ADR-0014：Episode 分组评分与低分候选生命周期

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联版本/任务：记忆系统阶段 C.3
- 取代：ADR-0013 第 3 节中的评分权重顺序；其事务、幂等和恢复决策保持有效
- 被取代：无

## 背景

ADR-0013 固定了 Consolidator 的事务和幂等边界，但其中评分示例误把时间与实体权重写成
0.35/0.25。记忆设计书第 12 节和阶段 C 清单规定的顺序是实体 0.35、文本 0.25、时间
0.20、情绪与主题一致度 0.20。C.3 还需要明确低分分组怎样等待新 Fragment、怎样到期，
避免每次 worker 扫描都制造重复候选。

## 决策

### 评分公式

```text
total = entity_score   × 0.35
      + text_score     × 0.25
      + time_score     × 0.20
      + coherence_score× 0.20
```

- `entity_score`：全组共同实体数量 ÷ 全组实体并集数量。没有共同实体不形成分组。
- `text_score`：组内所有 Fragment 两两 trigram Jaccard 相似度的平均值。
- `time_score`：`1 - (组内时间跨度 / 7 天)`，限制在 0～1。
- `coherence_score`：emotion、scope、kind 三个字段各自的主值占比，再取平均。
- 四个分量和总分均限制在 0～1，并保存到数据库；阈值为 `total >= 0.50`。

### 分组边界

- 只读取最近 7 天内 active、enabled、未进入正式 Episode、未被 pending 高分候选占用的 Fragment。
- 必须具有至少一个全组共同的 active Entity；每组按时间排序，最少 2 条、最多 20 条，首尾
  跨度不得超过 7 天。
- 分组指纹为 `SHA-256(policy_version + 排序后的 Fragment ID)`，与标题、摘要和评分无关。
- 多个提案重叠时，按总分、来源数量、最早时间、指纹稳定排序；一次扫描中先选中的分组占用
  Fragment，防止生成互相冲突的高分候选。

### 低分生命周期

- 低于 0.50 的分组写入 `episode_group_candidates`，只保存 Fragment ID、共同 Entity ID、
  四个评分分量、总分、策略版本和时间，不保存正文或模型摘要。
- 同一指纹再次评估只增加 `evaluation_count` 并更新分数，不重置 `first_seen_at` 或 `expires_at`。
- 首次观察 7 天后转为 `expired`，退出活动重评；Fragment 不修改、不删除。
- 新 Fragment 形成不同指纹时，重叠的旧 observing 分组转为 `superseded`；同一指纹达到阈值
  时转为 `qualified` 并关联兼容高分候选。
- C.3 达到阈值后仍只建立兼容 pending Episode 候选；正式自动写入留给 C.5。

## 备选方案

### 只保存一个总分

- 优点：字段少。
- 缺点：无法解释为何成组，也无法校准某个分量。
- 未采用原因：不满足可审计与真实样本校准需要。

### 每次运行删除并重建低分分组

- 优点：实现简单。
- 缺点：无法计算七天生命周期，完全相同的低分组会永久重新出现。
- 未采用原因：会造成候选抖动且无法审计。

## 后果

### 正面后果

- 阈值判断可解释、可测试、可按真实样本校准。
- 低分组有明确等待与退出机制，不删除任何正式记忆。
- 指纹和稳定排序使重复运行结果一致。

### 代价与限制

- trigram 不是语义模型，近义表达可能低估文本相关度。
- 贪心消除重叠不保证全局最优，但行为稳定且容易审计。
- C.3 的高分结果仍需人工确认，直到 C.4/C.5 完成摘要校验与正式原子应用。

## 安全与隐私

- 权限等级：本地 S0。
- 涉及的数据：Fragment/Entity ID、分类字段和评分；低分表不保存正文。
- 是否访问网络：否。
- 是否产生外部副作用：否。
- 用户确认和审计方式：高分兼容候选可查看来源；低分表通过只读本地 API 查看评分与状态。

## 数据与迁移

- schema 14 为兼容候选增加评分字段，并新增 `episode_group_candidates`。
- 旧候选评分默认 0、策略版本为 `legacy`，不会伪装成 C.3 评分结果。
- 回滚时停止新评分器即可；表与字段保留，不删除 Fragment 或旧候选。

## 验证

- 自动测试：四分量、0.50 边界、2/20 条、7 天边界、共同实体、指纹幂等、重复评估、
  superseded/qualified/expired、正式 Episode 单一归属。
- 手工验收：本阶段没有新的主界面，不使用内置浏览器。
- 监控或日志：Consolidator run 记录处理结果，候选记录分量、策略版本和评估次数。

## 回滚

将 worker 暂时切回旧规则器并停止写入低分表。schema 14 保留向后兼容字段；已经生成的 pending
候选可继续由旧兼容入口处理，低分记录不参与召回或提示。
