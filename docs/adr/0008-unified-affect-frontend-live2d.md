# ADR-0008：前端与 Live2D 共享后端情绪快照

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联计划：`docs/AFFECT_AND_RELATIONSHIP_SYSTEM_PLAN.md` 阶段 4.1

## 背景

系统提示词已经使用后端 affect 快照，但右栏仍把工作模式当成心境，桌宠则从回复关键词
独立猜测表情，并在空闲时随机换脸。同一轮对话因此可能同时出现三种互相矛盾的状态。

## 决策

- 后端 `CompanionState` 是心境、关系和派生情绪簇的唯一真相。
- SSE `done` 中的 `companion_state` 负责聊天成功后的立即刷新；主窗口每 10 秒读取一次统一
  状态，接收懒推进和后台观察器稍后应用的变化。
- 短暂读取失败保留最后一份有效快照，不回退成前端虚构默认值。
- 工作模式与心境在 UI 中分开：模式描述当前工作动作，心境展示 `derived.label`。
- IPC 传递字段从旧 `emotion` 改名为 `cluster`；九簇映射集中在一份共享展示表中。
- Live2D 模式只控制动作，cluster 只控制表情；空闲动作不得随机改写表情。
- 未知 cluster 或模型表情缺失统一回退 neutral，任何桌宠故障都不阻止文字聊天。
- 内部连续值只在开发环境的折叠调试区显示，默认产品界面只展示可读标签和最近原因。

## 后果

- 系统提示词、右栏和 Live2D 能从同一后端快照解释当前状态。
- 观察器是后台执行的，因此桌宠表情可能在聊天完成后数秒再次更新；这是状态真实变化，
  不是前端抖动。
- 主窗口关闭时没有轮询；下次打开会立即获取当前快照。

## 回滚

保留统一状态类型和 API 客户端，停止 App 定时刷新及 cluster IPC 即可暂时关闭展示联动；
不得恢复回复关键词推断，因为它会重新建立第二份情绪真相。
