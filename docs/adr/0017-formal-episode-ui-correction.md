# ADR-0017：主界面只展示正式 Episode，纠错不改写来源链

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联版本/任务：记忆系统阶段 C.6
- 取代：旧 Episode 候选确认界面
- 被取代：否

## 背景

C.5 已经让 Consolidator 自主创建正式 Episode，但“记忆与关系”页面仍展示 pending 候选、可编辑
来源复选框以及接受/拒绝按钮，文案也声称候选不会自动成为正式经历。这既与真实行为冲突，也会让
用户误以为必须逐条确认。最终界面应让用户理解“遐蝶自主整理、用户可以查看来源并纠错”。

C.5 review 10/10 通过且无新增缺陷，并建议 C.6 展示 `summary_status` 和 `source_hash`，隐藏候选
确认按钮。该建议与本阶段目标一致，予以采纳。

## 决策

### 1. 主界面数据边界

- Episode 区域只调用 `/api/episodes` 和 `/api/episodes/{id}`，不读取 pending 候选；
- 主界面移除候选标题/摘要编辑器、来源复选框、接受与拒绝按钮；
- 旧候选查询、接受和拒绝 API 暂时保留，作为迁移兼容面，不在主界面暴露；
- “检查新经历”只排队后台 Consolidator，不同步生成、不要求用户确认。

### 2. 正式 Episode 详情

展开详情展示：

- 摘要正文与 `model_validated`、`extractive_fallback`、`user_edited`、`legacy_rule` 的中文解释；
- 来源内容哈希的 12 位短指纹；完整 64 位值仅在用户主动复制时使用；
- 整理方式、应用协议、分组策略、规则置信度；
- 有序来源 Fragment、来源日期、原对话是否仍可访问及跳转入口；
- 关联 active Entity、最近纠错时间与纠错说明。

短指纹用于辨认，不替代完整哈希，也不作为安全认证凭证。

### 3. 人工纠错语义

新增 `POST /api/episodes/{id}/correct`，允许纠正标题、摘要、重要度和说明：

- 使用 `BEGIN IMMEDIATE` 读取最新 active Episode 并原子更新；
- 标题或摘要变化时，`summary_status=user_edited`、协议改为 `manual-v1`、模型证据清空；
- 只调整重要度时保留原摘要状态与证据；
- 来源 Fragment 顺序、`source_fragment_ids`、`source_hash`、分组指纹和 candidate_id 永不由该端点修改；
- 写入独立 `corrected` / `user_correction` 记忆事件，区别于普通系统更新；
- 空标题、空摘要、非法重要度和已知敏感/注入内容被拒绝。

如果来源 Fragment 本身事实错误，用户仍应先在正式记忆详情中纠正 Fragment；Episode 的人工纠错
用于同步修正经历叙述，不反向覆盖 Fragment 事实。

### 4. 可访问性与响应式布局

- Episode 标题使用原生 button，并提供 `aria-expanded`；
- 校验状态不仅依赖颜色，同时始终显示文字标签与解释；
- 窄屏下标题、审计格和来源操作改为单列；
- 空状态明确说明自动形成条件，不再提示用户确认候选。

## 备选方案

### 继续展示候选，但默认折叠

- 优点：旧操作入口容易找到。
- 缺点：仍暗示用户需要审批自主记忆，增加认知冲突。
- 未采用原因：兼容 API 已足够支持迁移，主界面应表达最终产品行为。

### 直接显示完整 64 位来源哈希

- 优点：技术信息完整可见。
- 缺点：占据界面、普通用户难以辨认，容易喧宾夺主。
- 未采用原因：短指纹加主动复制兼顾可读性与审计需要。

### 纠错时允许增删来源 Fragment

- 优点：操作更自由。
- 缺点：会破坏 C.5 的分组指纹、摘要证据与单一归属边界，需要重新运行完整事实校验。
- 未采用原因：C.6 只允许纠正叙述和重要度，来源变更应通过未来专门的重组流程。

## 后果

### 正面后果

- 界面与自主 Episode 后台行为一致；
- 用户可以理解每条摘要是模型校验、原文回退、人工纠错还是旧版结果；
- 正式经历保留可读来源链与原对话入口；
- 人工纠错不会悄悄伪装成模型摘要或改变事实来源。

### 代价与限制

- 主界面不再处理遗留 pending Episode 候选，需要继续保留后端兼容 API；
- 当前没有 Episode 来源重组、归档或删除入口，这些属于后续生命周期阶段；
- 未使用内置浏览器做 UI 验收，依靠 TypeScript、生产构建、静态契约测试和代码审查验证。

## 安全与隐私

- 权限等级：本地 S0；纠错只修改本地 Episode，不访问网络或工具；
- 页面不显示完整 prompt、模型原始输出或 API Key；
- 完整来源哈希只响应用户主动复制；
- 原对话跳转仅在来源消息仍存在时显示。

## 数据与迁移

schema 17 为 `memory_episodes` 增加：

- `correction_note TEXT NOT NULL DEFAULT ''`；
- `corrected_at REAL`。

旧 Episode 默认没有纠错说明和时间，不伪造历史纠错。

## 验证

- 后端：纠错状态、协议、证据清空、来源不变、独立事件与非法输入；
- 前端：四种摘要状态文案、哈希短指纹、候选确认控件不再出现在 Episode 组件；
- 总验收：0.50 阈值、跨自然日七天窗口、来源/实体继承、幂等、失败回滚继续通过；
- TypeScript、Vite 生产构建与 Electron 脚本语法检查。

## 回滚

前端可回退到旧组件，但不建议重新启用候选确认作为主流程。schema 17 字段和纠错事件保留；停止
调用纠错端点不会影响现有 Episode 读取或自动合成。
