# ADR-0021：Saga 后台整理与原子应用

- 状态：Accepted
- 日期：2026-07-16
- 阶段：记忆系统 D.4

## 背景

D.1～D.3 已能确定性分组并生成受来源约束的 Saga 摘要，但候选仍不是正式长期故事。正式应用必须在
模型调用期间允许来源被纠正，又不能留下半个 Saga、重复归组或覆盖一份仍然正确的旧 Saga。

## 决策

1. `saga_consolidator_runs/events` 保存幂等任务、八态状态机和完整状态事件；同一 worker 每次只认领一个任务。
2. 模型摘要在写事务外完成。正式写入使用一个短 `BEGIN IMMEDIATE` 事务，单轮最多应用 5 个候选。
3. 写事务重新验证候选仍为 qualified、未晋升、分组指纹一致，所有 Episode 仍为 active/completed，
   Episode→Fragment 来源链有效，摘要整链哈希未变，且一个 Episode 不属于其他有效 Saga。
4. 新建时一次提交 Saga、有序 Episode、active Entity、Saga 事件、候选晋升和 run 终态，任一步失败整批回滚。
5. 自动追加只针对 active Saga。旧来源必须是新候选来源的严格有序前缀，旧 Saga 来源哈希必须仍有效；
   追加只增加后缀 Episode，并以完整新来源重算摘要、当前阶段、重要度和来源哈希。
6. 已晋升的旧短候选只作为历史证据，不再占用本轮 Episode，否则 `{A,B}` 会永久遮挡 `{A,B,C}` 的追加。
7. Episode 应用事务成功后只尝试幂等入队，入队失败不得回滚 Episode。启动或空闲时距上次成功超过
   6 天才排队周任务；失败最多三次指数退避，陈旧运行可恢复，取消在模型调用前后设置安全点。

## 审查取舍

- 采纳应用事务的 Episode 状态、单一归属、候选指纹和整链哈希复核。
- 采纳每轮摘要/应用上限，避免一次后台工作长时间占用本地资源。
- 保留 `user_edited` Episode 可作为正式来源；纠错本身不等于来源不可信。
- 仅 active Saga 可自动追加；completed 恢复及生命周期变化留给 D.5 的明确状态守卫。
- N13/N14 是既有体验项，不影响本阶段的原子性，继续延期。

## 后果与验收

聊天和 Episode 正式写入不等待 Saga 模型调用。重复任务、摘要失败、来源并发变化、跨 Saga 冲突或进程
中断不会产生部分正式数据，也不会改变旧 Saga 快照。验收覆盖创建、真实自动追加、幂等跳过、Entity
派生、事件、任务取消/恢复/重试和失败回滚；全量后端 175 项、前端 7 项及生产构建通过。
