# ADR-0001：本地 API 访问边界

- 状态：Accepted
- 日期：2026-07-14
- 决策者：项目维护者、Codex
- 关联版本/任务：v0.1.1 本地 API 访问保护
- 取代：无
- 被取代：无

## 背景

FastAPI 只监听 `127.0.0.1`，但此前允许任意网页来源调用，也没有应用级身份校验。用户浏览器中的普通网页因此可能尝试读取或修改本机遐蝶数据。后续文件、工具和自动化能力会放大这一风险。

## 决策

- 每个应用启动会话使用一枚高熵随机临时令牌；正式包使用 32 字节加密随机数，开发启动器使用两个独立 UUID 拼接。
- 正式包由 Electron 主进程生成令牌，通过子进程环境交给后端，通过受控 preload IPC 桥接交给渲染进程。
- 一键开发启动器因启动顺序需要，先生成约 244 bit 随机强度的临时令牌并交给后端和 Electron。
- 启动器或 Electron 将自身 PID 传给后端；后端看门狗在父进程消失时退出，避免带令牌的旧服务残留并占用固定端口。
- 前端在每个数据 API 请求的 `X-Xiadie-Token` Header 中携带令牌。
- 除最小健康检查外，后端所有 `/api/` 接口都校验令牌。
- CORS 只允许本机 Vite 开发源和 Electron `file://` 对应的 `null` Origin。
- `python run.py` 显式启用浏览器开发兼容：仅准确匹配本机 Vite Origin 时可以不带令牌。
- 令牌只存在于进程内存或子进程环境中，不写入 URL、日志、localStorage、SQLite 或配置文件。

## 备选方案

### 仅依赖环回地址和 CORS

- 优点：实现简单。
- 缺点：CORS 不是完整身份认证，非浏览器本地进程也不受限制。
- 未采用原因：无法支撑未来高权限工具。

### 固定令牌或用户配置密码

- 优点：多个进程容易共享。
- 缺点：需要持久化，容易泄露、复用或形成迁移负担。
- 未采用原因：本机单用户桌面应用不需要长期凭据。

## 后果

### 正面后果

- 普通网页和不知道临时令牌的本地程序不能调用数据接口。
- 每次启动自动轮换，不产生长期令牌管理负担。
- 后续工具协议可以复用同一应用身份边界。

### 代价与限制

- 手工启动三个进程时，需要使用 `run.py` 的严格来源开发兼容，或显式共享 `XIADIE_API_TOKEN`。
- 占用 8756 端口的旧后端不能被一键启动器直接复用，因为它不持有本次令牌。
- 进程环境并非操作系统级秘密保险箱；该令牌用于阻止跨网页和意外本地访问，不替代用户权限隔离。

## 安全与隐私

- 权限等级：本地应用身份验证，不授予具体工具权限。
- 涉及的数据：随机临时令牌，不包含用户内容。
- 是否访问网络：仅访问 `127.0.0.1`。
- 是否产生外部副作用：否。
- 用户确认和审计方式：启动时自动建立，不单独提示；认证失败不记录令牌。

## 数据与迁移

不改变 SQLite schema、数据位置或已有用户数据，无需迁移。

## 验证

- 自动测试覆盖无令牌、错误令牌、正确令牌、开发来源及 CORS 来源。
- 前端生产构建和 Electron 语法检查必须通过。
- 打包链路需在产生正式安装包时再次验证 Electron 令牌传递与后端重启。

## 回滚

可以回退中间件、前端 Header 和 Electron 桥接代码，不影响已有数据。回滚会重新暴露原有本地 API 风险，因此只允许用于故障定位，不作为发布方案。

## 后续事项

- [ ] 正式打包后验证后端异常退出与重启时令牌仍一致。
- [ ] 工具系统加入独立的用户权限和操作确认，不把本令牌当成工具授权。
