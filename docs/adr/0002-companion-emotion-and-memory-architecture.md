# ADR-0002：伴侣情绪状态与星座记忆采用单后端分层架构

- 状态：Superseded
- 日期：2026-07-14
- 决策者：项目所有者、Codex
- 关联版本/任务：jiwen 与 MemoryConstellations 融合
- 取代：无
- 被取代：ADR-0004（拆分短期心境与长期关系）

## 背景

遐蝶当前有固定人格提示和单表三层记忆。用户希望融合 jiwen 的连续情绪/主动性设计与 MemoryConstellations 的分层记忆和星图。后者本身是独立 Express 应用，直接并入会形成第二套服务、认证、数据库与前端，增加启动、退出、端口和数据一致性问题。

## 决策

- 保持 Electron + React + FastAPI + SQLite 的单应用架构。
- 在 FastAPI 中实现 Python 原生 CompanionState，先只影响回复语气。
- 记忆按 Fragment、Entity、Episode、Saga 渐进扩展，保留来源和审计。
- 第一版检索使用 SQLite；向量数据库通过接口延后评估。
- 主动通知默认不实现，待权限与调度基础齐备后另行决策。
- 采用概念级重构并标注灵感来源；直接移植代码时保留对应开源许可。

## 备选方案

### 方案 A：把两个 Node 项目作为子服务运行

- 优点：较快获得原项目全部功能。
- 缺点：三个运行时、多端口、多数据库，退出清理和打包显著复杂。
- 未采用原因：与当前单后端、本地可靠和渐进实施原则冲突。

### 方案 B：只做外观相似的星图

- 优点：展示快。
- 缺点：没有来源、生命周期和检索能力，无法形成真实记忆系统。
- 未采用原因：只复制视觉，不解决用户需要的 Agent 能力。

## 后果

### 正面后果

- 复用现有启动、鉴权、数据库和前端边界。
- 每层能力可单独测试、迁移和回滚。
- 情绪状态与事实记忆不会互相污染。

### 代价与限制

- 不能立即获得 MemoryConstellations 的完整功能。
- 需要重新实现数据模型、归档流程和可视化。
- 在主动调度完成前，jiwen 的主动联系能力保持关闭。

## 安全与隐私

- 权限等级：当前阶段 S0，仅本地状态计算；后续远程抽取按模型调用披露。
- 涉及的数据：对话派生状态、记忆内容、来源消息和实体关系。
- 是否访问网络：当前情绪状态不访问；远程模型和 embedding 沿用供应商配置。
- 是否产生外部副作用：当前无。
- 用户确认和审计方式：记忆候选须可见、可拒绝；主动功能须显式开启。

## 数据与迁移

- schema 或存储变化：新增 schema 版本表和 `companion_state`；后续记忆表另做迁移。
- 兼容旧数据的方法：当前没有正式用户数据；未版本化开发库视为版本 0。首次保存真实数据前可直接完成记忆表重构。
- 失败恢复方法：迁移保持幂等；开发阶段可删除空库重新初始化，产生真实数据后再增加事务、备份与恢复验证。

## 验证

- 自动测试：迁移幂等、状态边界、持久化、提示注入、失败不提交。
- 手工验收：连续对话后状态变化，重启仍可读取，不产生主动弹窗。
- 监控或日志：当前仅通过本地只读 API 检查，不记录聊天正文到额外日志。

## 回滚

停止在聊天提示中注入状态即可恢复旧行为。保留 `companion_state` 表不会影响旧版本；确认无需保留数据后可通过专门迁移删除，不在普通回滚中破坏性删表。
