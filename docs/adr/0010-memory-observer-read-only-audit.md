# ADR-0010：记忆观察器的只读后台审计边界

- 状态：Accepted
- 日期：2026-07-15
- 决策者：项目所有者、Codex
- 关联计划：`docs/MEMORY_SYSTEM_DESIGN_FOR_BEGINNERS.md` 阶段 B.2

## 背景

B.1 已建立严格协议，但还没有真实模型调用。若直接在聊天 SSE 中调用观察模型，会延迟回复；
若过早复用正式写入事务，又会让“模型输出通过校验”和“获得记忆写权限”混成一步。

## 决策

- 成功对话只同步插入幂等任务，随后立即发送 SSE `done`；模型调用由独立后台任务完成。
- B.2 后台任务的终点固定为 `validated`，只保存净化后的候选、警告、稳定错误码、模型、
  token、字符数、耗时和协议版本。不得写 `memory_fragments`、实体关系或记忆事件。
- 观察模型可跟随当前聊天模型，也可选择已启用的真实独立模型；`mock` 永远不能作为独立
  观察模型。
- JSON 先经过 B.1 的确定性围栏清理和唯一完整对象提取。仍为 `invalid_json` 或
  `schema_invalid` 时，整个任务最多调用一次受限格式修复；修复输入标为不可信且必须再次
  通过完整协议校验。
- 失败任务不保存原始模型正文、异常正文或对话副本，只保存安全错误码和非内容型统计。
  中断的 `running` 任务由 worker 扫描恢复，读取审计 API 本身保持只读。
- B.2 暂时保留旧关键词候选流程。B.3 才能在单一事务中把 `validated` 候选转成正式 Fragment。

## 后果

- 可以用真实模型观察调用质量与成本，而不会改变用户的正式记忆库。
- 观察器失败、超时或格式错误不会阻塞聊天；同一助手消息的并发入队只产生一条任务。
- B.3 可以直接复用队列与恢复能力，重点审查去重、实体关系和正式写入事务。

## 回滚

停止记忆观察 worker 并移除聊天入队即可恢复 B.1 行为。`validated` 审计行和 schema 11 的
耗时/修复字段可以保留；它们不会参与召回，也不会被当作正式 Fragment。
