# ADR-0038：本地影子知识召回协议

- 状态：已接受
- 日期：2026-07-16
- 阶段：K.2

## 背景

显式知识检索已经存在，但自然对话是否应查知识库尚无可验证的判断协议。直接把自然命中片段注入聊天会同时引入误触发、远传授权和延迟风险，因此必须先观察真实判断结果。

## 决策

1. 使用 `knowledge-recall-decision-v1`。动作固定为 `skip/retrieve/ask`，原因使用稳定 reason code，判断完全在本地完成，不调用远程分类模型。
2. schema 36 新增 `knowledge_recall_decisions`。只保存查询哈希、计数、原因、置信档、耗时、检索降级、协议版本、策略快照哈希和 Provider 位置 revision；不保存查询正文、候选正文、文件名、document/chunk ID 或模型原始输出。
3. 影子任务在独立后台线程执行。聊天热路径只写一条无正文 queued 记录并入队；召回判断不读取或修改本轮模型消息，因此建议 `retrieve` 也不会注入资料。
4. 显式禁止、寒暄、情绪支持、简单任务和歧义短句在检索前跳过。显式资料请求仍可作为影子判定的高置信原因，但现有显式检索回答不由影子结果控制。
5. 候选由本地 FTS 与已建立的 BGE-M3 dense 索引生成。模型缺失或向量异常保留 FTS；FTS 无词项时允许 vector-only；全部失败时安全记录 skip/failed。
6. 单次后台判断预算 1500 ms。超预算结果标记 `timed_out`，不影响已经进行的聊天。此阶段不尝试强制杀死本地推理线程。
7. 文档策略集合参与判断，但只持久化包含文档 ID、策略和 revision 的不可逆快照哈希；Provider 保存位置与 revision 快照。位置变更提示和授权凭证分别留在 K.4。

## 后果

- K.3 可以用无正文记录校准阈值和评测协议。
- 影子模式产生额外本地 CPU/磁盘读取，但不占用聊天事件循环，也不上传查询或知识正文。
- 后台线程超时是“结果作废”而非进程级抢占；若后续实测资源争用明显，再评估独立进程执行器。
