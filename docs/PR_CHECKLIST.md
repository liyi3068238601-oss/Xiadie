## 2. 范围控制

- [ ] 已列出准备修改的模块和文件。
- [ ] 本次只解决一个主要问题，附带改动与它直接相关。
- [ ] 预计修改不超过 8-12 个主要文件。
- [ ] 若超过 15 个主要文件，先暂停并拆成更小步骤。
- [ ] 没有顺手重构无关代码。
- [ ] 没有提交用户数据、密钥、日志、模型或授权受限资源。

## 3. 开工前检查

- [ ] 阅读 `docs/CODEX_PROJECT_CONTEXT.md`。
- [ ] 对照 `docs/XIADIE_LONG_TERM_ROADMAP.md`，确认没有跨阶段抢做。
- [ ] 检查 `git status`，保留用户已有的无关修改。
- [ ] 记录变更前的验证结果或复现步骤。
- [ ] 涉及重大技术决策时已创建 ADR。

## 4. 风险判断

- [ ] 是否会删除、覆盖或迁移本地数据？
- [ ] 是否会读取或写入用户文件？
- [ ] 是否会访问网络或向外部服务发送内容？
- [ ] 是否会执行命令、控制浏览器或控制桌面？
- [ ] 是否会新增权限、密钥或隐私数据？
- [ ] 是否会改变默认端口、进程、启动或退出行为？

任一项为“是”时，必须写清楚权限等级、确认时机、失败恢复和回滚方案。

## 5. 实现检查

- [ ] 输入在后端边界完成校验。
- [ ] 错误对用户可理解，日志不泄露密钥或隐私。
- [ ] 长任务有明确的进行中、成功、失败或取消状态。
- [ ] 外部副作用默认最小化，并在执行前按权限规则确认。
- [ ] 数据结构变化包含 schema 版本或迁移方案。
- [ ] 新配置有安全默认值和缺省降级行为。
- [ ] UI 没有把占位能力伪装成已经可用。

## 6. 验证矩阵

按改动范围执行，不要求无关层每次全部重跑；合并到稳定版本前应完成全量验证。

| 范围 | 最低验证 |
|---|---|
| 后端 | `cd backend; .\.venv\Scripts\python.exe -m pytest tests -q` |
| 前端 | `cd frontend; npm.cmd run build` |
| Electron | `cd desktop; node --check main.js; node --check preload.js` |
| 启动链路 | 双击 `启动遐蝶.bat`，确认桌宠、主窗口、退出清理及日志 |
| 数据变更 | 用旧数据库升级，验证成功、重复执行和失败回滚 |
| 权限/工具 | 验证允许、拒绝、取消、超时和审计记录 |

本次结果：

- [ ] 自动测试通过。
- [ ] 构建或语法检查通过。
- [ ] 关键手工路径通过。
- [ ] 已记录仍存在但可接受的警告。
