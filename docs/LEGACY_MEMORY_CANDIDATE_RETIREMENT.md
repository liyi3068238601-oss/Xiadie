# 旧版记忆候选兼容与退役策略

状态：Accepted

日期：2026-07-15

## 目标

`memory_candidates` 是自主记忆上线前的人工确认原型。它现在只在观察模型不可用或重试耗尽
时作为保守兜底，不能再作为真实模型路径的主入口。本策略确保旧 pending 数据不会因界面
切换而丢失，也不会长期混淆“自主记忆”和“待确认候选”。

## 当前兼容方式

- 记忆页主区域只展示正式 Fragment。
- pending 候选保留在页面底部默认折叠的“旧版候选兼容区”。
- 用户仍可查看来源、修改内容与层级、接受或拒绝。
- 接受后沿用现有 `auto_confirmed` 来源；不会伪装成 observer 自主记忆。
- 数据库表、API 和历史 accepted/rejected 审计在 B.4 均不删除。

## 允许退役入口的前置条件

以下条件必须全部满足，才能在后续独立阶段提出删除兼容入口：

1. pending 数量为 0，或项目所有者明确决定如何处理剩余项。
2. 连续至少一个稳定版本没有依赖人工候选完成正常模型记忆流程。
3. 模型不可用时已有替代的非确认式降级策略，或明确接受“不自动记忆”。
4. 导出/备份能够保留 candidates 及其 memory_events。
5. 删除前有迁移测试、回滚说明和单独 review，不与其他记忆阶段捆绑施工。

## 当前明确不做

- 不自动接受旧 pending 候选。
- 不批量拒绝或物理删除历史候选。
- 不把旧候选改写为 observer 来源。
- 不因当前开发库数据很少而绕过来源与审计要求。

因此，B.4 完成的是“主界面退场、兼容入口保留、退役条件固定”，不是删除旧系统。
