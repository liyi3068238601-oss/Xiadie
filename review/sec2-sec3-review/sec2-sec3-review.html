🔍 后端 regenerate 逻辑深度验证
regenerate 流程时序
# main.py chat() — regenerate=True 路径 # 1. 查找最后一条 assistant 消息 ID（line 258-264） last = conn.execute( "SELECT id FROM messages WHERE session_id=? AND role='assistant'" " ORDER BY created_at DESC LIMIT 1", ... ) if last: replace_assistant_id = last["id"] # 2. 查找最后一条 user 消息 ID（line 265-270） last_user = conn.execute( "SELECT id FROM messages WHERE session_id=? AND role='user'" " ORDER BY created_at DESC,id DESC LIMIT 1", ... ) # 3. 不插入新 user 消息（line 303: if not body.regenerate） # 4. 不触发记忆/情绪观察（line 473: if not body.regenerate） # 5. 不触发知识影子召回（line 372: if not body.regenerate and ...） # 6. 流式生成 — 失败时直接 return，不触及 DB async for chunk in llm.stream_chat(provider, model, messages): collected.append(chunk) yield _sse("delta", {"text": chunk}) # ↓ LLMError → yield error + return（旧回复安全保留） # 7. 成功时：INSERT 新回复 → DELETE 旧回复 → COMMIT（同一事务） c2.execute("INSERT INTO messages(...) VALUES(...)") if replace_assistant_id: c2.execute("DELETE FROM messages WHERE id = ?", (replace_assistant_id,)) c2.commit()

安全保证：(1) 新回复完整生成后才写库；(2) INSERT 和 DELETE 在同一事务； (3) 生成失败时 gen() 直接 return，不执行写库；(4) 旧回复在 DELETE 前始终存在。

建议 1：修正 SEC.3 计划书勾选状态（P0）

建议 2：前端 regenerate 失败时恢复旧回复显示
虽然后端保留了旧回复，但前端在 regenerate 失败后可能显示空白或错误状态。 建议在 ChatView.tsx 中：当 regenerate=true 且收到 event: error 时， 重新从 GET /api/sessions/{id}/messages 加载消息列表，恢复旧回复的显示。 这样用户能看到旧回复仍在，而不是看到空白或错误。这是一个轻量改动，不需要等到 UI 伴侣化阶段。
建议 3：SEC.2 context_budget 专项测试补充
当前 context_budget 模块无专项测试。建议补充：(1) get_context_window 对已知/未知 Provider 返回值测试；(2) estimate_tokens 对空/短/长文本的估算测试；(3) trim_history 边界测试—— 历史刚好等于预算、历史远超预算、历史为空、单轮对话不可裁剪；(4) SSE meta 中 context_trimmed 和 context_trimmed_messages 的端到端验证。
建议 4：regenerate 的知识引用处理
当 regenerate=true 且知识检索产生了新引用时，旧回复的引用记录会被 DELETE FROM messages 级联清理，但新回复的引用在 INSERT 后写入。建议验证：(1) 旧 knowledge_message_citations 是否随旧消息删除而清理；(2) 新引用是否正确关联到新消息 ID；(3) knowledge_chat_retrievals 的 assistant_message_id 是否更新为新 ID。当前测试未覆盖 regenerate + 知识引用的组合场景。
建议 5：SEC.1 SecretStore 测试补充（遗留）
上次审查提出的 SEC.1 无专项测试问题仍未解决。建议在进入阶段三（代码结构治理）前补充 test_secret_store.py，覆盖 SqliteSecretStore/InMemorySecretStore 的基本操作和 provider 集成。
